# 接入与持续工作流

## 初次接入

先挑一个常改系统，如技能。沿真实链路查：Markdown 规则 -> Excel/CSV -> DataTable -> 读取该表的组件/蓝图 -> 运行时覆盖值。记录行 UStruct、软引用和加载位置；不要只搜一个同名变量就认定它是唯一生效点。

复制 starter 中的清单后替换示例路径。每个 dataset 是一个完整的逻辑表，每个 view 包含同一组受管字段。字段可用 columns 映射显示名。未映射字段只在原文件保留，不跨文件传播；新行的未映射字段没有来源，因此应先检查其默认值。CSV 给 Excel 使用时 ID 列按文本导入，防止前导零丢失。

首次数据不同：列差异，由用户既有意图或项目事实选择合并结果，先把所有侧改到一致，再 init。不能为“初始化成功”任意选择一边。基线与映射应纳入项目版本管理；`.design-sync/sync.lock`、pending、last-transaction、last-report、UE 临时请求应忽略，事务备份可能包含项目内容，不向外发布。

记录语义映射 `design-links.json`（starter 有实例），每项至少包含：

- `id`：稳定 feature ID。
- `files`：相关策划、表、代码、资产路径，必须真实存在。
- `rule_anchor` / `implementation`：定位规则与调用链。
- `acceptance`：给定条件、操作、期望结果；涉及随机性时固定种子或给范围。

`impact_scan.py acknowledge` 建立逐文件 hash 复核基线，check 报告变化和受影响 feature。它只检测文件变化，不能证明文档语义与实现一致；必须结合 diff 和验收。只修改清单增删映射同样会被识别，不能靠移除文件掩盖漂移。

扫描范围只包含已映射文件；新系统、新文件或没有映射的实现需要从项目实际 diff 中发现并补入映射。报告 clean 不能推导整个游戏所有文件已覆盖。

## 使用场景

| 入口 | 执行结果 |
|---|---|
| “火球伤害 100 改 120” | 找行 ID、确认单位/作用域，改受管字段、块外公式示例和相关测试；同步，导入 UE，验证实际命中 |
| 在 DataTable 编辑器调冷却 | 保存 -> 导出最新表 -> 三方比较 -> 同步 Excel/CSV/Markdown；检查 C++/蓝图是否仍硬编码旧值 |
| “长按蓄力，松开发射” | 修改系统规则、状态机、取消条件、输入逻辑、可配参数与验收场景；代码/蓝图编译和 PIE |
| Excel 改值同时代码改其他字段 | 不同字段合并；同字段不同值报告冲突；不使用最后写入者获胜 |
| 删除技能 | 检查跨表、蓝图软引用、存档/网络协议，再迁移或废弃；不能只删一行 |
| 只调整 Markdown 排版 | 确认规则未变，保留格式修改；不生成无关代码改动 |

## 项目 AGENTS.md 追加片段

只在真实项目接入时合入，保留现有内容：

```markdown
## 游戏策划与实现联动
本项目使用 $game-design-sync。涉及玩法规则、数值、配置字段、DataTable、C++ 或蓝图行为时，读取 design-sync.json 与 design-links.json，沿 feature 映射更新受影响的策划案、配表、实现与验收场景。
编辑前检查已有数据/语义漂移；保留用户未提交修改。UE 数据先保存并导出，再三方同步。冲突不得按时间戳覆盖。同步后执行字段校验、DataTable 回读、相关编译及行为验收；无法运行 UE 时明确列为未验证。语义复核完成才 acknowledge。
```

## 保存事件、CI 与团队协作

当前包提供命令和 agent 闭环，没有安装后台服务。确定性同步可接用户现有编辑器保存任务/CI：保存完成后防抖，等待 Excel 锁释放，以单次任务执行 plan/apply；忽略 `.design-sync` 与导出临时文件，比较内容 hash 防回环；冲突、检查失败或语义变化停止自动应用并报告。不要自动重置基线、无限重试或后台改蓝图。

CI 执行数据 check 和语义 check，非零退出应阻止声称“一致”。`check` 不执行任意项目检查命令；编译/Automation 另设 CI 任务。多分支合并后，连同基线与源文件共同审查。不要跨机器同步活动 lock/pending，也不把一个工作区的基线强推到另一分支。

## 失败与恢复

脚本快照针对本次 apply 开始前的文件，因此会保留用户已修改的源值。检查失败恢复到 apply 前，非失败改动仍可供重新解决。跨文件不是操作系统级原子提交；有持久 pending 日志和独占锁，崩溃后先确认进程停止，移除失效 lock，然后 recover。恢复后重开 UE/Excel，避免缓存把旧内容写回。

只保证清单中的受管文件与 rollback_paths；检查命令可能产生构建产物、日志或外部副作用，不能宣称全部回滚。`last-transaction.json` 保存最近一次前后文件快照，手工回滚前必须逐文件比较当前 hash 与 after；如有后续编辑，先保留并合并，不能直接恢复旧备份覆盖。代码/蓝图语义修改使用各自精确补丁和资源快照，不用整体 git reset。
